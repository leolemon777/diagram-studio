# 软件、网络、机架、目录与线框

本批输入位于 `assets/software-infrastructure-models/`，统一由 `scripts/software_infrastructure.py` 校验和重绘。内容均为模拟数据；先替换输入，再把图用于实际方案或实施。

## 选择模式

- `chen-erd`：概念数据模型。矩形为实体、菱形为联系、椭圆为属性；弱实体和标识联系用双框。每个实体至少有一个键属性，每个联系逐角色记录基数与参与约束。物理表、外键和 DDL 另做关系模型。
- `network-topology`：设备和逐端口链路。每台设备保留角色、层次、厂商/型号和管理地址；每条链路保留两端接口、L2/L3、容量、介质、目的、网段和证据。`cisco-campus` 还要求核心、汇聚、接入层；图中只用中性徽标，不捆绑厂商图标包。
- `rack-elevation`：前视或后视 U 位。校验设备不越界、不重叠，并计算占用/空余 U 和输入功率。1U 为 44.45 mm。承重、供电回路、散热和线缆弯曲半径不由本图证明。
- `active-directory`：林、域、OU、对象、委派、GPO 链接和信任的逻辑视图。对象必须位于所属 OU；OU 父子关系不能跨域或形成环。站点、子网与复制连接属于物理拓扑，另图表达。
- `network-location`：地点容器和跨站连接。地点与路径来源必须明确；容量、时延、运营商和介质逐边保存。当前只接受 `schematic`，不把示意位置当经纬度或比例地图。
- `ui-wireframe`：网站、iOS、Android 低保真结构。交互元素必须有动作和可访问名称。网站同时提供 1440 与 320 CSS px 视图并保留页面地标；iOS 显式上下安全区和标签栏；Android 显式系统栏、权限/键盘状态与返回行为。

## 输出与验收

每份输入输出 SVG、PNG、原始输入 JSON、计算摘要和 QA。编辑时保留稳定 ID，先改 JSON，再重算和重绘。浏览器检查需打开实际 SVG，确认标题、节点、边、端口、边界、状态和页脚没有遮挡或裁切；JSON 可解析不能代替成图检查。

来源边界：Chen 采用原始论文入口；Cisco、Microsoft、Apple、Android 和 W3C 采用官方公开文档；机架概念采用厂商公开教育资料。这些来源用于语义和结构，不代表产品认证、规范符合性或真实配置验证。
