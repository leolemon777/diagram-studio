## 登录后实看：四种模板与编辑器

2026-09-20，用户完成登录后，通过“使用此模板”打开四份独立模板白板，实际查看画布。以下是可见设计观察，不能据此推断全部会员库质量或内部算法。研究副本保留在用户空间，不把账户信息、白板链接或商业模板素材提交到仓库。

| 实际打开的模板 | 可见设计 | 独立吸收规则 |
|---|---|---|
| 引导式头脑风暴（入口标会员免费） | 编号步骤、参与者分组便签、汇总区域；示例与空白板并列 | 将发散、整理、收敛分区；每区说明输入与产出。参与者颜色不能被误读为优先级；空白区不填造假结果 |
| 设计提炼情绪板 | 图片、色板与关键词形成主题簇，曲线表达联想；有说明栏和空白骨架 | 图片簇按命题组织，说明借鉴的色彩/质感/构图；关系线要有含义。文字方向板与含合法图片的情绪板明确区分 |
| 帆船回顾（入口标会员免费） | 海面上呈现阳光、风、灯塔；水下分为团队内部、团队外部与组织层面的阻碍 | 可用隐喻促进讨论，但保留直白标签：目标、助力、阻力、风险。类别间区别必须写清，不依赖装饰识别；正式分析可切换为朴素分区 |
| 用户故事地图 | 横向卡片序列，纵向分层与分隔线；完整示例和空白结构并列 | 用户顺序与交付分层使用两套明确标题；保留跨层列对齐，不把空缺当零或自动补齐。具体发布切片仍由用户事实决定 |

编辑器实际检查了缩放菜单、总览全部和图钉列表。总览能容纳整板，但正文变小；图钉列表有缩略图，所见两项名称均为“未命名的节点”。因此本 Skill 的独立要求是：**总览用于定位，正文另有清晰尺寸；导航使用任务名称，不能只用编号或“未命名”。** 阅读模式、演示等只看到入口，未验证完整操作；不声称已经实现这些产品功能。

### 选型与验收规则

1. 先判断目的：共同产出用步骤工作区；比较视觉方向用主题簇；回顾助力与阻碍可用语义隐喻；规划体验与交付用二维层次。
2. 提供一小段原创示例帮助理解填法，再提供对应空白输入说明；明显标注示例，不能把模拟内容混入用户事实。
3. 每个空间区有任务标题、输入与预期输出。装饰不能压过内容；颜色之外仍有文字标签。
4. 新颖布局至少检查起点、阅读顺序、分类含义、例外位置，以及小屏幕/静态输出是否仍能理解；未检查的范围必须说明。
5. 长画布提供有名称的持续导航和清晰尺寸。切换章节保留各图阅读状态，当前章节对键盘和辅助技术可辨识。

本轮将第 5 条落到现有示例阅读页：吸顶章节导航、当前章节标记、返回总览、可聚焦滚动区。其余为生成时执行的设计规则，没有新增四种专用自动渲染器，也没有复制上述模板。

## 新颖表达应如何接收

允许新的图元组合、空间组织和交互。按用户任务选择，不能只靠是否已有模板判断能否制作。

- **故事地图 / release slices**：横向为用户活动顺序，其下是具体任务；纵向为明确的交付切片。切片应能支撑一个可用体验，不是任意颜色分组。故事 ID 稳定；跨切片引用不能让同一工作被重复计数。无日期时不画成比例时间轴。v43 已新增专用生成器；输入、测量排版、示例与验收范围见 [故事地图](story-map.md)。
- **复盘的分歧区**：除停止、开始、继续外，保留有争议的判断与待补证据；拟议动作和已确认承诺分开。静态行动表可由现有后端实现。
- **事件风暴 / event storming**：探索页有此入口。适合软件与业务共同梳理发生过的业务事件，事件、触发动作、参与者和未解问题采用不同语义。此轮只有方法入口，未研究完整领域建模规范，也没有专用渲染实现。
- **灵感板 / moodboard**：探索页有设计情绪板入口。适合品牌、教学、空间与内容提案；围绕具体风格命题组织参考，标注来源和“借鉴哪一点”，不靠杂乱拼贴营造丰富。素材需由用户提供或合法取得；没有素材时只做文字方向板，不虚构参考作品。
- **多视图叙事**：同一模型可以给出主题分组、用户阶段和行动清单等不同阅读入口，使用 ID 回链。只有事实一致才可并列比较；不同图回答不同问题，不要求外形统一。

新结构的交付要点：读者能找到起点、方向、分组含义与例外；用图例解释陌生编码；静态导出仍保留关键含义。不要把新颖自动等同于更优，也不把新方案锁定为全局默认。

## 五条可执行的工作方法

1. **保留观察**：每条原话有 ID 与来源；整理或合并后仍可回溯原话。分组由助手推断时明确标注。少数意见和不符合主题的材料放在可见区。
2. **区分证据与假说**：旅程先明确用户、目标、场景和阶段。行为、触点、观察、机会分开；没有情绪量表就不画虚构情绪曲线。
3. **有依据地收敛**：只有给出真实票数和规则才绘投票结果。说明参与范围、每人票额、是否允许集中投票；票数表示偏好，不证明价值或代表性。影响/工作量矩阵必须有轴含义与依据；缺数据时用待讨论分类，不编造坐标。
4. **追踪行动**：观察或主题→拟议动作→负责人→复核日期→验收方式。未确定项写待定；不能把假设写成用户承诺。多视图中的改动回到同一个源模型。
5. **按场景组合**：教育反馈用亲和归纳和课程改进；零售体验用旅程与后台蓝图；营销复盘用观察与行动；产品交付用故事地图和计划。不要把所有场景收敛成工业流程。

## UI/UX：吸收方法，保持自己的视觉表达

| 设计原则 | 本轮落实 / 后续边界 |
|---|---|
| 按目的进入 | 选图向导增加“洞察与共创”；四个入口有不同语义缩略图 |
| 先看为什么，再填什么 | 每种图解释适用问题和最少输入；用户无需先懂术语 |
| 原型与实际能力分开 | 显示可运行示例、模型编辑或方法配方状态，并链接实际案例 |
| 逐步提供细节 | 先呈现选型理由，再读详细规则和源模型；避免主画面塞满工具 |
| 选择可逆 | 切换图型、风格和语言保留已输入内容；重绘控件后保持键盘焦点 |
| 空间为阅读服务 | 总览用于定位，正文需要清晰尺寸；大图内部滚动或拆页，不靠缩字塞满 |
| 多元视觉体系 | 调研、汇报、叙事、技术图可各有构图与气质；颜色只承担明确角色，不强制同一皮肤 |

这不是 Boardmix UI 复刻，也没有新增实时多人编辑、聊天、投票服务、云历史版本或 `.bdx` 导出。要实现这些产品功能，需要单独的软件开发与验收。

## 原创示例与复现

[三个跨行业示例](../demos/workshop-study/index.html)，源数据在 `assets/workshop-examples/`，全部为原创模拟输入。

```bash
python3 scripts/organization_relations.py assets/workshop-examples/education-affinity.json --out output/workshop
python3 scripts/render.py assets/workshop-examples/retail-journey.json --out output/workshop
python3 scripts/render.py assets/workshop-examples/marketing-retrospective.json --out output/workshop
```

亲和图需 Matplotlib，交付 SVG/PNG 与可重绘 JSON；本后端没有 draw.io。两个表格例交付 SVG、draw.io、源 JSON 与几何 QA。亲和图已验证观察完整且唯一归组；表格几何 QA 通过不等于语义自动验收。此轮未对这些例子做原生编辑器检查，后续换内容需再次查看实际图形。
