# 按内容排版

## 选择与输入

v38 的 `render.py` 接入 `adaptive_layout.py`，生成命令保持不变。

- 树图、分层架构默认启用；graph 未给 x/y/row/col/groups 时默认启用。
- `"layout":{"mode":"adaptive","direction":"auto"}` 显式重新排版，方向也可限制为 `right` 或 `down`。
- `"layout":{"mode":"fixed"}` 或 `legacy` 使用原排版器。已给坐标的 graph 默认保留原坐标。带坐标分区的图须保留，或先由助手将分区含义建成层级模型。
- 标准图的特殊符号、专业计算或坐标含义不能为使用此引擎而丢失。

节点使用稳定 `id`、完整 `label`、可选 `detail`。边保留 `from/to/label/arrow/dashed`。无需填写尺寸和路由；自适应会重算这些布局字段。树图保持 `root/children`，架构保持 `layers/items` 与可选 `crosscut`。同层模块可换行；显式 `edges` 才代表实际连接，分层本身不制造调用关系。

自然语言由当前助手理解。只根据已给信息提取名称、解释、分组和关系，必要时保留出处。脚本不会擅自摘要或删除长文字。

## 引擎选择与修正

先测量文字，再比较框宽、横排、竖排、流程折行与树分支排列，按交叉、密度和预计窗口阅读比例择优。保留中文换行、尾行平衡和拉丁单词；普通标题 22、说明 17，菱形和椭圆另外留出内部空间。

正交连线寻找避障通道，反馈和自循环保留；标签避开节点与其他标签。第一轮不满足条件时扩大通道重试，仍失败则返回具体问题，由助手调整分组后重绘。候选、选中参数和交叉数写入 scene/QA；评分衡量几何取舍，不是审美分数。

真实字宽使用可选 Pillow，本机优先系统黑体，Linux 使用 Noto CJK，Windows 使用雅黑。`DIAGRAM_FONT` 可指向已有字体，不会自动下载。缺少字体或 Pillow 时记录 `conservative-estimate` 并使用保守估算。度量字体名写入 SVG；换电脑缺少字体时需重新查看。

## 阅读交付

生成 `name.html`、SVG、普通和多页 draw.io、brief、scene、QA 与 `name-reading.json`。

- 总览保留全部节点和关系，画布可扩展，不声称大画布仍为 16:9。
- 局部关系页保留子图的完整名称和内部连接，跨页关系用 R 编号追到索引；完整说明放在对象详解。
- 对象详解按 1600×900 分页；长说明自动续页，不截断、不无限缩字。
- 完整关系索引保留每条原关系的源、目标、标签与对象页码。

`reading.json` 记录对象到页码的映射和每条关系的来源。无法在标准页容纳的局部图由总览和完整对象/关系页承载，不强塞。详页不替代任何领域标准要求的完整单图。

## 实际视觉修正

在浏览器打开阅读 HTML。`browser_quality.js` 等待 SVG 字体后读取 `getBBox`，检查文字容器与菱形内部边界。页面状态及 `#quality` 的 `data-report` 保存本页结果，可通过只读 DOM 能力读取。

再查看整页和最密区域：主路径是否清楚，反馈是否误认为前进，标签是否靠近对应线，正文在交付尺寸是否可读，是否有过多无用空白。失败时当前助手修正并重绘，直到问题解决或遇到具体的输入约束。不要只看统计值。脚本只做有限候选几何优化，实际审美与语义修正仍由助手承担。

draw.io 节点、关系端点和多页结构均保留。只有实际打开、移动、保存和重开后，才能说已验证编辑行为。

## 回归和边界

`scripts/adaptive_examples.py --out <dir>` 生成教育树、零售流程、软件架构和产品反馈四个模拟压力案例。`tests/test_v38_adaptive.py` 检查内容与关系保留、修改重排、超长续页、避障、主题、固定坐标、源端点和 63 份既有范例基本兼容性。

上限为 160 个语义对象，超过时先按含义建立相互引用的模型。专用后端、任意形状、任意深度容器和全部目标编辑器不在此次自动覆盖范围。测试通过不代表任意复杂内容已经获得审美签收。
