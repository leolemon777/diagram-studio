# 受约束流程与网站地图

`governed_flow.py` 使用可编辑 JSON 建模，并保留可编辑 DOT 源文件。内置确定性矢量布局器负责 SVG/PNG 输出，因此解压重绘不依赖系统安装 Graphviz。所有示例均标为模拟数据。

## EPC 事件流程

- 节点限定为事件、功能和 AND/XOR/OR 逻辑门。
- 不经过逻辑门时，事件与功能必须交替；逻辑门之间不能直接连接。
- 起点和终点必须为事件，每个逻辑门必须承担分支或汇合。
- EPC 表达事件驱动过程，不用于消息先后或普通时间表。

## 审计流程

- 每个工作节点都需要责任角色，每个判定都需要唯一证据编号和判定依据。
- 每个判定必须同时具有“通过”和“不通过”分支。
- 不通过分支必须进入整改，经过复核后返回原判定；所有节点最终都能到达结束。

## 程序流程

- 节点限定为开始、输入、处理、判定、输出和结束。
- 每个判定提供可判定条件，并同时具有“是”和“否”分支。
- 所有节点从开始可达且都能到达结束；每个循环强连通分量必须存在退出边。
- 嵌套过深时改用 N-S 图或结构化伪代码。

## 网站地图

- 页面 ID 和根相对 URL 必须唯一；页面层级必须形成单根连通树。
- 层级边与跨页任务链接分开保存和绘制，跨页链接不能重复父子关系。
- 页面访问级别限定为 public、internal 或 admin，并在节点文字中明确标注。

## 验证边界

后端验证当前示例的图语法、连接引用、可达性和模式专用约束。它不证明模拟流程符合现场制度，也不验证程序已经实现或网站权限已经部署。
