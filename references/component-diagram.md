# UML组件图：组件、端口与接口协作

依据 OMG UML 2.5.1 第11.6节，组件是封装内容且可在环境中替换的模块化单元。组件通过提供接口说明对外服务，通过要求接口说明依赖的服务；这些接口可以由端口组织。逻辑组件和物理组件都可建模，但组件协作图不自动等同于部署图。

当前 `component_model.py` 输入包含 `title`、`scope`、非空 `assumptions`、`components`、`interfaces`、`ports` 和 `relations`。组件必须有唯一网格位置；端口必须引用已有组件和接口，并明确 `provided` 或 `required`、边界方位及顺序。

关系语义：

- `assembly` 从要求端口连接到提供端口。两端必须引用同一接口；当前教学子集限制每个端口只参与一条装配连接。
- `dependency` 从客户组件指向供应组件，使用虚线开放箭头；它表示未进一步限定的依赖，不表示部署节点或物理链路。
- 提供接口使用 lollipop 圆形符号，要求接口使用开放 socket 符号；端口是组件边界上的小方形。

组件使用带 `«component»` 的分类器矩形，并同时展示 UML 组件图标。draw.io 中图标、端口和接口符号是组件子单元，连接保留源/目标绑定。

教学输入 `assets/component-models/maintenance-components.json` 展示六个逻辑组件、四个接口、八个简单端口、四条装配连接和一条普通依赖。当前源已在 draw.io 完成一次文字编辑、下载保存、结构比对和重开：60 个单元、13 条边、父子关系、源/目标绑定、样式、几何和路径点保持，六个组件、组件图标、端口、四条装配及一条依赖在 60% 视图可见。证据见 `research/component-roundtrip-validation.json`。当前覆盖黑盒接口协作；长标签、组件实现、制品、内部 parts、委派连接、协议行为、多重性和部署视图仍需逐项验证。
