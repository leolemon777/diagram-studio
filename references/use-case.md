# UML用例图：输入、方向与边界

依据 OMG UML 2.5.1 第18章：用例表达主体向参与者或其他利益相关方提供的有价值行为；参与者是与主体交互的角色，可以是人员、外部硬件或其他系统。用例用椭圆表示，主体可用命名矩形边界表示；边界内的视觉包含不自动表示模型所有权。

当前 `usecase_model.py` 输入包含 `title`、`scope`、非空 `assumptions`、`subjects`、`actors`、`use_cases` 和 `relations`。标识符全局唯一，主体、参与者和用例必须有名称。渲染器当前只接受一个主体，所有用例必须应用于该主体。

关系语义：

- `association` 只连接一个参与者与一个用例；当前限二元关联。可输入端点多重性，但生成器不推断多人如何共同参与。
- `include` 从包含方/基础用例指向被包含的公共用例，使用带 `«include»` 标签的虚线开放箭头；禁止直接或间接自包含。
- `extend` 从扩展用例指向被扩展的基础用例，使用带 `«extend»` 标签的虚线开放箭头；必须列出属于被扩展用例的扩展点，可附条件。
- `generalization` 当前只允许同类端点，即参与者到参与者或用例到用例；尚未覆盖全部重定义约束。

`usecase_render.py` 将参与者画成 UML 允许的 `«actor»` 分类器矩形；用例为椭圆，主体为容器。draw.io 中用例是主体子单元，关系保留源/目标绑定。图只表示目标与关系，不表示行为步骤；详细步骤应放在文字规格、活动图、交互或状态机中。

教学输入 `assets/usecase-models/maintenance-use-cases.json` 展示三个参与者、五个用例、四条参与关联、三条包含关系和一条条件扩展。当前源已在 draw.io 把“验证身份”改为“验证身份 · 重开”，保存后重新打开；全部单元 ID、样式、父子关系、关系绑定、几何和路径点与源文件一致，只有目标文字值变化。当前证据仅覆盖这一单主体教学图；多主体、长中文压力、参与者/用例泛化、复杂扩展点、包所有权和大型自动布局仍需逐项验证。
