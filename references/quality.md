# 语义、视觉与交付检查

## 证据等级

- `example_available`：存在可运行的输入，只证明该输入可作为起点。
- `generated_with_semantic_validation`：模型通过该后端的结构、算术或关系检查后生成；不代表字体、视觉或领域结论已批准。
- `rendered_visual_check`：已运行的真实渲染边界检查通过；不代表人工视觉签收。
- `manual_visual_review`：有人实际打开指定输出检查过整图与密集区域。除非记录了编辑器、领域评审或签收，它也不代表那些检查已经完成。

当前批次的实际范围记录在 [验证状态](verification-status.md)，不要从目录数量反推任何一级状态。

## 语义先行

节点集合、边集合与输入逐项对照；无编造的实体/性能/数值。图型与任务相符。树检查环和多父；流程检查分支出口；时序检查消息顺序；ER 检查键与基数；图表核对数据；甘特核对日期/依赖。

## 机器检查与实际查看

`render.py` 检查 ID、端点、有限坐标、页面边界、文本估算和非容器对象相交，并生成 `.qa.json`。这不能证明中文实际字体无溢出、所有连线无遮挡、工程/标准语义正确。

v38 自适应模式增加字体度量、候选重排、避障与标签检查。离线阅读 HTML 另在浏览器实际读取 SVG 文字边界，结果保存在页面 `#quality` 的 `data-report`。生成时 QA 的 `rendered_visual_check` 仍为 `not-run`，直到实际运行浏览器检查并另存证据；不把字宽度量混称为浏览器验收。

`cross_industry.py` 与 `remaining_types.py` 还使用 `matplotlib_quality.py`：在 Matplotlib 完成绘制和选字体后，读取实际文字边界，检查页面/显式容器溢出、文字间相交和缺字警告。它不检查路径是否被遮挡、不执行 draw.io 重开，也不判断医学、工程或科学内容是否真实正确。

打开 SVG/HTML 看整页；再查看最密区域。检查：标题是否截断，长中文是否溢出，主路径能否追踪，标签是否落在正确边，线是否穿过无关节点，主题对比是否足够。需要修复则改模型、留通道、拆分或调整字级。

## 可编辑性

- brief JSON：重新生成用，保存原始事实和假设。
- scene JSON：排版后的对象坐标和边，审查/进一步加工用。
- SVG：矢量对象与文字，不等于任何目标软件原生兼容。
- drawio：原生 XML 节点、文本、连线；用实际编辑器打开、选择文字或移动节点后核对连接，再声称验证可编辑。
- 不以改名方式生成 eddx/vsdx/pptx。指定格式需要对应工具转换并重开。

## 修改回归

检查这次改动可能影响的部分：新增节点的连接、换主题的对比、长文字的换行、日期变更的条宽。不要仅因为脚本运行成功就宣称图“审核通过”。
